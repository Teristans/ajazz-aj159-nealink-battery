# 黑爵 AJ159 星闪版电量托盘

黑爵（AJAZZ）**AJ159 NL / NL P（星闪 NearLink）** 无线鼠标的 Windows 托盘电量显示。
直接读 HID，**不需要黑爵官方驱动、不联网、不改鼠标设置**。

| 项目 | 值 |
|---|---|
| 接收器 | `7768:6425` "AJAZZ NearLink" |
| 插线时的鼠标本体 | `7768:6D25` 一类（型号相关） |
| 协议 | input/output report，report id `6`，无 feature report |

本文档按 **2026-11 在 AJ159 星闪版上的本机实测**记录。

> 如果你用的是 **AJ179 APEX**（`3151` Sonix 2.4G、带 OLED 充电底座），请用另一个仓库：
> [ajazz-aj179-battery-tray](https://github.com/Teristans/ajazz-aj179-battery-tray)。
> 本程序的代码虽然也能自动识别 AJ179 并读出电量（见文末「兼容」），但那个型号的完整说明与
> 底座对时功能都在旧仓库里。

## 文件

| 文件 | 作用 |
|---|---|
| `启动 鼠标电量.bat` | 双击启动（找 pythonw 并拉起托盘） |
| `ajazz_tray.py` | 托盘程序：图标、菜单、通知、开机自启 |
| `ajazz_battery.py` | 协议核心：星闪为主，附带 AJ179 兼容读取；可直接运行查看原始帧 |
| `requirements.txt` | 依赖清单 |
| `config.json` | 运行时生成（对话框设置） |
| `quit.flag` | 运行时临时文件（`--quit` 用，用完自动删） |

文件名用 `ajazz_` 品牌前缀，与只支持 AJ179 的旧版 `aj179_*` 区分开，两个版本可以并存。

## 使用

双击 `启动 鼠标电量.bat`，托盘出现数字电量图标：

- 数字 = 电量百分比。绿（>50%）/ 橙（21–50%）/ 红（≤20%）；充电时为蓝色
- `充` = 已插线但读不到百分比
- `--` = 鼠标休眠 / 接收器未插
- 左键点击 = 立即刷新（默认每 60 秒自动刷新；鼠标休眠时缩到 15 秒，醒来能快点显示）
- 悬停 = 电量与更新时间
- 右键 = 电量详情 / 开机自动启动 / 退出

电量 ≤20% 时弹一次系统通知。

**底座时钟**这一组菜单项只在插入 AJ179 的 Sonix 接收器时出现；星闪版接收器没有 OLED 底座，
程序会自动隐藏该组选项（本仓库以星闪版为主，这部分属于兼容保留）。

开机自启：右键菜单勾选「开机自动启动」（写入 `HKCU\...\CurrentVersion\Run`，不建快捷方式、不留残留文件）。文件夹挪位置后请取消再勾选一次。

命令行（排查用）：

```bash
python ajazz_tray.py --once          # 输出 JSON（含 protocol / clock_synced）
python ajazz_tray.py --sync-clock    # 只对一次时（当前没接底座时返回 false）
python ajazz_battery.py              # 人类可读 + 原始帧
python ajazz_battery.py --watch      # 每 2 秒读一次，边动鼠标边看
```

## 协议：星闪 / NearLink（VID 0x7768）

和 AJ179 那一套**完全不同**，移植时最容易踩的坑是 feature report：

- 厂商集合是 `usage_page=0xFFB2`（同一接口上还有 `0xFFB1` / `0xFFB3`），
  `FeatureReportByteLength = 0` —— **没有 feature report**，只能走 input/output report。
- report id `6`，帧长 64，结构固定：

```
06 | class | len(=1+载荷长度) | 00 | 00 | type | 载荷...
```

- 读电量：写 `06 05 01 00 00 00`（class `0x05` = 鼠标信息块，type 0），回复：

```
06 05 24 00 00 01 | 00 25 6d 15 10 01 01 5a 00 00 06 03 07 00 0f 00 ...
                ^^                    ^^
                载荷[0]               载荷[7] = 0x5a = 90%
```

载荷布局（实测）：`[1..2]` 产品 PID、`[7]` 电量、`[10]` DPI 档位数、`[11]` 当前档、
`[12..23]` 六个 u16 小端 `dpi/50-1`（实测 400/800/1200/1600/2400/3200）、`[24]` 回报率索引。

- **鼠标休眠时不会回信息块**，接收器改推一条链路通知：

```
06 fa 02 00 00 01 00
                ^^ ^^
                tag 0x01(链路) = 0（未连接）
```

这条比"等超时"快得多，程序收到就立刻判定为休眠，不再空等。电量推送帧是同族的
`06 fa 03 00 00 03 64 01`（tag `0x03`，百分比 `0x64`，第二字节为充电标志）。

- **充电判定靠"本体是否在线"**：插上 Type-C 后鼠标本体会作为独立 USB 设备枚举
  （`7768:6D25` 一类），接收器可能仍在线。所以"本体在线"就是"已接 USB"。
  接收器转发的充电标志恒为 1，不可信，程序不使用它。

- 写之前要**先排空残留帧**，否则会读到上一次查询的旧答案（写对了看起来像被拒）。

只发 `class 0x05 / type 0` 这一条只读查询帧。协议里的 `class 0x12`、`0x31` 会清除设备里的
按键映射（有开发者在逆向时两次踩到，只能靠恢复出厂设置找回），本程序完全不碰。

## 兼容：AJ179 APEX（Sonix 2.4G，VID 0x3151）

本仓库只针对星闪版。程序里保留了另一套 Sonix 协议的读取代码，所以插上 AJ179 的接收器也能正常
显示电量——但完整说明、帧格式、以及**充电底座 OLED 对时**都在
[ajazz-aj179-battery-tray](https://github.com/Teristans/ajazz-aj179-battery-tray)。

这里只列三个「不知道就会踩」的点：

- 读取前必须先发 `0xF7` 心跳把 2.4G 遥测链路拉起来，否则状态页永远是全零；电量在
  GET_FEATURE report `0x05` 的 byte3。
- 底座时钟走 `0x28 SET_OLEDCLOCK`，帧里必须带 `0xD7` 标记，而且必须每 30 秒重发
  （底座会自己把时间重置回 `00:00`）。
- 这套接收器带 OLED 底座，托盘右键菜单会因此多出「底座显示时间」一组；星闪版没有底座，
  该组会被自动隐藏。

## 环境

Python 3.11+ 与 `hidapi`、`pystray`、`pillow`：

```bash
pip install -r requirements.txt
```

`启动 鼠标电量.bat` 会依次在常见安装路径和 PATH 里找 `pythonw.exe`（不再写死绝对路径）；
也可以直接编辑那一行换成自己的路径。

## 已知限制

- 鼠标深度休眠时接收器不返回电量，显示 `--` 并保留上次读数；动一下鼠标，下一次刷新（≤15 秒）恢复。
- 星闪版的充电/放电靠"本体是否在线"区分，读不到"充电到 xx%"这类精细状态。
- 星闪接收器没有底座，因此没有 OLED 时钟功能。
- 星闪协议里 `class 0x12 / 0x31` 会破坏按键映射，本程序不发送任何写命令（只读 `0x05`）。
- 按 VID + 厂商集合特征匹配，同方案其他黑爵型号大概率可用，未逐一实测；本体 PID 未知时会按产品名（是否含 "NearLink"）区分接收器与鼠标本体。
